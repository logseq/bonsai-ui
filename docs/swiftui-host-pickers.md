# SwiftUI civil picker services

`Host_effect.pick_date`, `pick_date_range`, and `pick_time` now use the owned
SwiftUI application window. A shared `NativeHostDialogs` presenter serializes
menus and civil pickers through one sheet lifecycle. File dialogs and existing
native/declarative modals also occupy that modal slot.

## Public API and domain

Dates are proleptic Gregorian components in years 1 through 9999. Inclusive
`first` and `last` bounds are required. The optional date initial value defaults
to `first`; an omitted range starts and ends at `first`. All supplied components,
initial values and range ordering are validated before OCaml queues a request.
No arbitrary civil date is converted through Foundation Calendar: its historical
cutover would change values such as October 10, 1582.

The sheet uses native SwiftUI Year, Month and Day menu Pickers, reusing
`CivilDateDomain`. Changing the year/month preserves or clamps the other fields;
February 29, 2024 becomes February 28 when changing to 2025. Range start changes
advance the end when needed, and end choices are restricted to start through the
inclusive upper bound. Options are generated by year/month, without expanding
all days in the supported interval.

Time uses SwiftUI DatePicker with hour-and-minute components and a fixed UTC
reference date. The OCaml result remains civil hours/minutes, independent of
local time zone or daylight saving transitions. `format` is `System` by default;
`Hour12` and `Hour24` change the hour cycle while preserving the locale. The
Flutter calendar/dial, entry-mode, current-day and `use_24_hour` arguments and
wire fields are removed, with no compatibility decoder.

Edits remain local to the sheet until Save. Save returns `Ok (Some value)`;
Cancel or user dismissal returns `Ok None`. Explicit request cancellation,
inactivity, hidden or detached windows cancel pending work. A visible sheet owns
the modal slot until native dismissal completes. Background application input
is blocked and notification timeout accounting pauses while a dialog is open.
Presenter/request UUIDs fence retained actions across cancellation and restart.
Draft bindings also reject obsolete field snapshots within one request.

## BSFR 5.0 payloads

Request headers retain their existing request IDs and kind IDs. All integer
fields use the protocol's little-endian encoding.

| Kind | Request payload after request ID and kind | Successful response |
| --- | --- | --- |
| 16, date | Optional initial date, first date, last date | Optional selected date |
| 17, date range | Optional initial start/end pair, first date, last date | Optional selected start/end pair |
| 18, time | Hour UInt8, minute UInt8, format UInt8 (`0/1/2`) | Optional selected hour/minute |

A date is year UInt16, month UInt8, day UInt8. An optional value begins with a
strict `0/1` presence byte. OCaml encode/decode and Swift decode reject invalid
components, reversed bounds/ranges, out-of-bounds initial values and invalid
format tags. The containing frame rejects trailing fields before execution.
Both request and response readers consume fields sequentially; OCaml argument
or record evaluation order is never used to advance the byte reader.

## Example and verification

Host Effects includes Choose date, Choose date range and Choose time. Its
standalone window test presses each real OCaml button, saves the native sheet,
and verifies the resulting visible date/range/time status.

`HostPickerServiceTests.swift` links the actual OCaml runtime. It edits real
NSPopUpButton menu actions and NSDatePicker actions, checks no early OCaml
response, saves values, cancels all three forms, tests menu/file contention,
blocks background actions, cancels inactivity and fences old Save actions after
restart. It also verifies a 360-point parent, historical dates, leap-day
clamping, omitted initial values, UTC time and malformed/truncated wire input.
Existing menu and civil widget tests remain applicable to their shared code.

Reproduce from the worktree:

```sh
opam exec --switch=bonsai-ui -- dune build @all @runtest @fmt @install
python3 tool/run_swift_tests.py
python3 native/test/test_host_effects_window.py
python3 tool/test_swift_platforms.py
```
