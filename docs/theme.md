# Shared UI defaults

`Theme.create` configures the application root or a `View.theme` subtree. Omitted
properties inherit the nearest scope. Explicit component properties win over
scoped overrides, which win over library defaults. Changing a theme updates the
existing view hierarchy and retains input controllers, focus and application
state. `System` mode inherits the platform appearance; omitted tint, font family
and control size inherit too. Control tint and decorative material tint are
separate values.

All shared baseline declarations live in `Theme.Defaults.Values` in
[`ocaml/ui/theme.ml`](../ocaml/ui/theme.ml). `Theme.Defaults.create` supplies sparse
scope overrides. Widget constructors retain omission; they do not substitute
concrete themeable defaults. `Theme.Defaults.standard` supplies the explicit
library baseline when requested. Native baseline data is generated by evaluating
the OCaml declarations, with no JSON source or separately maintained Swift table.

```ocaml
let defaults =
  Ui.Theme.Defaults.create
    ~symbol_size:21.
    ~column_spacing:12.
    ~symbol_rendering:Hierarchical
    ~colors:[ Ui.Style.Color_role.Primary, ink
            ; Secondary, muted
            ; Material_tint, paper_tint ]
    ~text_sizes:[ Ui.Style.Text_role.Page_title, 26. ]
    ()
in
let theme = Ui.Theme.create ~defaults () in
App.View.create ~theme ~body:(Ui.View.Body.static content)
```

Nested scopes only replace supplied values, including individual color and text
roles. A theme never materializes inherited values into component properties.
The native environment resolves them when drawing. Duplicate role overrides,
nonfinite numbers, nonpositive icon/text sizes, negative distances and alpha/opacity
values outside `[0, 1]` are rejected. Shadow X permits negative finite offsets. Zero column spacing is an intentional override.

## Icons and controls

Ordinary `View.symbol` glyphs use **19 points**, monochrome rendering and the
inherited foreground. `~size`, `~color` and `~rendering` remain explicit exceptions.
For a secondary icon, apply a local `Theme.Defaults.create ~foreground:Secondary`.
`~symbol_rendering` on Theme selects the inherited symbol rendering mode. An
explicit `View.symbol ~rendering:Monochrome` remains monochrome inside a Theme
that selects Hierarchical, even though Monochrome is the library baseline.

On **iOS/iPadOS**, ordinary button/menu labels containing symbols get a minimum
44 × 44 point target. Actionable rows, toggle/disclosure labels and native text
fields have a 44-point minimum height. The target is part of layout, including
padding, and neighboring controls do not receive overlapping expanded regions.
Explicit Mini/Small control sizes retain compact native behavior. **macOS has no
44-point minimum.** Button styling remains Automatic unless explicitly selected.

## Text roles

Select a role with `Style.Text_style.create ~role`, then pass it to `View.text`.
The inherited role is selected by `Theme.Defaults.create ~text_role`; the library
baseline is Body. `~text_sizes`, `~text_weights`, `~text_foregrounds` and
`~text_italics` override individual roles. Explicit role, size, weight, foreground,
color and italic values on text override the applicable Theme configuration. A native inherited font remains applicable to ordinary Body text.

| Role | Base points | Weight | Foreground |
| --- | ---: | --- | --- |
| Body | 17 | Normal | Inherited |
| Page_title | 24 | Bold | Inherited |
| Sheet_title | 19 | Medium | Inherited |
| Editor_title | 22 | Bold | Inherited |
| Empty_title | 20 | Bold | Inherited |
| Caption | 14 | Normal | Inherited |
| Hint | 13 | Normal | Secondary |
| Section_label | 12 | Normal | Secondary |

System fonts are the default. iOS Dynamic Type scales the base size; Bold Text
uses the native legibility environment. Leading/trailing alignment follows
layout direction. `~italic:true` is explicit, as is reading-body
`~line_spacing:4.`; ordinary labels and fields do not add reading line spacing.
Native text fields and editors use the same Body size, weight and foreground
configuration. Rich text inherits scoped typography too; explicit span attributes
win. Omitted italic inherits, while `~italic:false` explicitly disables it.
Custom font families refer to fonts already installed or bundled
by the host.

## Color roles

`Style.Color_role` includes Primary, Secondary, Page, Card, Inset, Search, Border,
Shadow and Material_tint. Absent colors use native semantic platform colors,
which respond to appearance and contrast. No light mode or fixed application
palette is imposed. `Text_style.create ~foreground` selects a role for text;
scoped foreground also applies to symbols. Explicit ARGB values intentionally
remain fixed application overrides, including alpha.

## Spacing and surfaces

Ordinary columns, including weighted columns, default to 16-point spacing. Rows
retain native spacing except within Material_action_group. Explicit spacing,
alignment and frame constraints remain authoritative.

`Theme.Defaults.Values.Spacing` exposes `xs`, `small`, `medium`, `regular`, `large`, `xl`: 4, 8, 12,
16, 24, 32 points. `Theme.Defaults.Values` exposes named base metrics for explicit styles
and image clipping. Their OCaml declarations are the
source for native defaults; use `make protocol-generate` after editing them.
`make protocol-check` verifies that the generated native baseline is current.

Use `Native_widget.Surface.create ~recipe` for opt-in paint:

| Recipe | Settings |
| --- | --- |
| Plain | Page background, opacity 1, no border or shadow |
| Material_action_group | Thin material, material tint, capsule, 0.7-point border; shadow radius 14, Y 6; row spacing 2; horizontal/vertical inset 6/2 |
| Content_card | Card background, corner 20, optional fine border |
| Inset_section | Inset background, corner 8 |
| Search | Search background, corner 10 |
| Translucent_sheet | Ultra thin material, zero tint alpha, paint opacity 0.4, corner 28, optional fine border |

Theme also configures recipes through `~surface_materials`, `~surface_shapes`,
`~surface_backgrounds`, `~surface_opacities` and `~surface_tint_alphas`. Each accepts
a typed list keyed by `Theme.Surface_role`: Unstyled (no recipe selected), Plain,
Material_action_group, Content_card, Inset_section, Translucent_sheet or Search.
Material choices are Solid, Thin, Regular and Ultra_thin; shape choices are
Rounded and Capsule. Background values select existing semantic color roles.

```ocaml
Ui.Theme.Defaults.create
  ~text_foregrounds:[ Hint, Primary ]
  ~text_italics:[ Hint, true ]
  ~surface_materials:[ Material_action_group, Regular ]
  ~surface_shapes:[ Material_action_group, Rounded ]
  ~surface_opacities:[ Translucent_sheet, 0.75 ]
  ~surface_tint_alphas:[ Translucent_sheet, 0.5 ]
  ()
```

`~shadow_x`, `~shadow_alpha` and `~material_alpha` configure the remaining shared
shadow and semantic material-color defaults. Explicit ARGB role overrides retain
their supplied alpha. Recipe tint alpha replaces the selected background's alpha;
when absent, it inherits the recipe baseline (zero for Translucent_sheet, otherwise
the selected color's alpha). Explicit Surface fill bypasses recipe paint selection.

Supplying a border color enables the optional fine border; an explicit width
of zero disables it. Explicit fill, corners, border, shadow and opacity override
the recipe. `~shape:Capsule` derives its radius from the actual height;
`~shape:Rounded` overrides a capsule recipe. `~content_inset:true` selects the
16-point page/editor inset. No ordinary primitive receives implicit padding.

Recipes use the [existing Surface paint path](swiftui-surfaces.md). Children stay
fully opaque. Reduce Transparency replaces material with opaque RGB paint at
opacity 1. Recipes do not change sheet detents, sizing, keyboard avoidance or
full-height native opacity. Presentation background remains an explicit option.

Note demonstrates application palette overrides, omitted ordinary configuration,
reading-body spacing and explicit miniature/decorative exceptions. Mail, Gallery
and standalone consumers share the same defaults.
